## Ответы на контрольные вопросы

1. Workflow состоит из события (on), заданий (jobs), у каждого задания есть runner (runs-on) и шаги (steps). Шаг может быть командой (run) или готовым action (uses). Вложенность: workflow, job, step.

2. Job — набор шагов, который выполняется на одной виртуальной машине. Jobs по умолчанию идут параллельно и изолированы друг от друга. Step — отдельная команда или action внутри job, шаги выполняются по порядку в одной среде.

3. Запуск по push срабатывает автоматически при отправке коммитов в репозиторий. Запуск через workflow_dispatch выполняется вручную кнопкой Run workflow во вкладке Actions.

4. Пароль или токен нужно хранить в Secrets репозитория (Settings, Secrets and variables, Actions) и использовать как secrets.ИМЯ. В коде значения нет, а в логе оно маскируется звёздочками.

5. Артефакт — файл, сохранённый по итогам запуска workflow. Нужен, чтобы передавать файлы между jobs, потому что у каждого job своя машина, и чтобы хранить результаты работы (сборки, отчёты) для скачивания.

6. Чтобы один job дождался другого, используется ключ needs. Линтер нужен, потому что он находит потенциальные ошибки и плохой стиль без запуска кода. В нашей работе тест остался зелёным, а shellcheck нашёл неэкранированную переменную.
